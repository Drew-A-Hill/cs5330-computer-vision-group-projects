1. PROJECT OVERVIEW (200 words or less)
================================================================================

This project implements a camera calibration and augmented reality system using
OpenCV. The system detects a 9x6 internal corner chessboard pattern from a live
video feed, calibrates the camera by collecting multiple views of the target, and
computes the camera's intrinsic parameters (focal length, principal point, and
distortion coefficients). Using these parameters, the system estimates the
chessboard's pose in real time via solvePnP, enabling the projection of 3D virtual
objects onto the board. We built two virtual objects, a house with a chimney and
a rocket ship, that float above the board and maintain correct orientation as
the camera moves. The system also includes a feature to hide the checkerboard
target by filling it with the surrounding color, making the virtual objects
appear to float on a blank surface. Additionally, a separate program detects
robust features using Harris corner detection and ORB, demonstrating how
feature-based approaches could replace the checkerboard for AR applications. The
system supports multiple input sources including mobile IP camera, static
images, and pre-recorded video.

================================================================================
2. TASK 1: DETECT AND EXTRACT TARGET CORNERS
================================================================================

Target type: Standard chessboard pattern with 9 columns x 6 rows of internal
corners (10x7 squares).

The system uses OpenCV's findChessboardCorners() with adaptive thresholding and
image normalization flags, followed by cornerSubPix() for sub-pixel accuracy.
Detected corners are visualized using drawChessboardCorners().

Limitations and challenges:
- Glare on screens displaying the pattern (especially on tablets/phones) can
  prevent detection. Adjusting the angle or lighting helps.
- The webcam had more difficulty detecting the pattern compared to the mobile
  camera, likely due to lower resolution and auto-exposure.
- The entire chessboard must be visible in the frame — partial views fail.
- Very steep viewing angles reduce detection reliability.

5. TASK 4: CALCULATE CURRENT POSITION OF THE CAMERA
================================================================================

The AR mode loads the saved intrinsics and uses solvePnP() to compute the
board's pose (rotation and translation vectors) for each frame.

How rotation and translation change with camera movement:
- Moving the camera left/right: The X component of the translation vector
  changes, which makes sense as the board shifts horizontally relative to the
  camera.
- Moving the camera up/down: The Y component of the translation vector changes.
- Moving the camera closer/farther: The Z component of the translation vector
  changes (increases when moving away, decreases when moving closer).
- Tilting/rotating the camera: The rotation vector components change
  correspondingly. These values behave as expected based on the camera's
  physical movement relative to the board.

6. TASK 5: PROJECT 3D AXES
================================================================================

Using the estimated pose, we project 3D coordinate axes onto the board origin
using projectPoints(). The axes are drawn as colored arrows:
- Green arrow: X-axis
- Blue arrow: Y-axis (pointing into the board)
- Red arrow: Z-axis (pointing up, away from the board)

The axes track correctly with the board as the camera moves around and maintain
proper perspective.

8. TASK 7: DETECT ROBUST FEATURES
================================================================================

A separate program (features.cpp) detects and displays two types of features:

HARRIS CORNERS:
- Detects points where image intensity changes significantly in multiple
  directions.
- On the checkerboard, Harris reliably finds the intersection points of the
  black and white squares.
- On the Tesla logo, it found only 8 points at the sharpest corners.
- Adjustable threshold (press +/- to change).

ORB (Oriented FAST and Rotated BRIEF):
- Finds FAST keypoints and computes binary descriptors for each.
- Detects many more features than Harris, including edges and textured regions.
- On the Tesla logo, it found features along the curves, edges, and text.
- Adjustable max features count (press +/- to change).

How feature points could enable AR:
Feature points like ORB could replace the checkerboard for AR by matching
descriptors between a known reference image and the live video frame. By finding
enough point correspondences, you can compute a homography or use solvePnP to
estimate the camera pose relative to the reference object. This allows AR to work
with any textured planar surface — a book cover, poster, or painting — rather
than requiring a specific calibration pattern. ORB is particularly suited for
this because it provides rotation-invariant descriptors that can be matched
quickly.

9. EXTENSIONS
================================================================================

EXTENSION 1: HIDE THE TARGET
We implemented a feature that hides the checkerboard by projecting the outer
board boundary (extending 1 square beyond the internal corners) and filling the
region with the average color sampled from just outside the boundary. This makes
the checkerboard disappear while the virtual objects remain visible, creating a
more convincing AR effect. Press 't' to toggle this feature on/off.

EXTENSION 2: CREATIVE VIRTUAL OBJECTS
We built two distinct 3D virtual objects — a house with chimney and a rocket
ship. Both use multiple colors, are more complex than basic geometric primitives,
and are asymmetric to aid in verifying correct orientation. The rocket features
an octagonal body, nose cone, four fins, a window, and exhaust flames.
Users can toggle between objects by pressing 'r'.

EXTENSION 3: STATIC IMAGE AR
The system supports loading a static image of the checkerboard and overlaying
virtual objects onto it using the saved intrinsic parameters. Run with:
./main ar img <path_to_image>
While the detection and projection work, the results are not as clean as with
live video. A perfectly flat, head-on checkerboard image gives solvePnP very
little perspective information to estimate depth, causing the virtual object to
appear stretched or distorted. Images taken at an angle produce better results
but still lack the real-time feedback that makes live AR compelling. This
extension is most useful for demonstrating the system on pre-captured scenes
without needing a live camera.
